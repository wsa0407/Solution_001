# 知识库：历史文档入库、召回与写章硬门

日期：2026-08-17  
状态：已共识，未实现  
范围：历史文档元数据、RAGFlow 作为存储/解析层、8002 双通道召回、`Citation` 与质检、与属地检索确认并存。  
不在范围：改 `TRANSITIONS`、3080 / DeepSeek Harness 自带知识库、让 agent 直连 RAGFlow 写正文、本期启用初设/招标等新文类、fork harness。

## 1. 一句话

10 多 G 历史项目材料进知识库，写章时**文类不串、属地不串**。RAGFlow 只负责解析和检索；8002 决定哪些 chunk 能进哪一章。地方政策仍只许同属地历史 + 属地库 + 已确认的实时检索。3080 不提供知识库服务。

## 2. 决策日志

| 决策 | 选择 | 不选 |
|---|---|---|
| 历史文档用途 | 写章参考：同文类给结构/模块/投资写法；地区特色只给地区章，且必须同属地 | 整段外地可研进新稿；只给操作者查阅、完全不进写手 |
| 文类隔离 | 建议书只召回历史建议书；可研对可研；立项对立项 | 七个阶段混库只按语义相似度 |
| 外地材料 vs 地区章 | 外地历史一律不准进地区 / 政策 / 编制依据章 | 外地地区章当模板再换地名；同方向换市名抄市情 |
| 阶段 vs 文类 | 写章只召回立项 / 建议书 / 可研。初设、招投标、调研、商机前入库打标，不进写手 | 初设进建设方案槽、招标进投资槽 |
| 存储 | RAGFlow 当入库与向量检索；8002 `retrieve()` 调它并后过滤 | 继续把 10G 摊成 JSON；3080 插件直连 RAGFlow |
| 实时地方政策 | 仍走 8002 DeepSeek 原生 `web_search`，属地过滤；与知识库互补 | 用 RAGFlow 代替公开网页检索 |
| 确认 | 地区/政策口径须可核验；实时检索命中进写章前须人确认方向（另案，见第 8 节） | 检索完静默开写 |
| 产品参数 | 仍以产品库 `params` 为质检口径 | 历史可研里的指标覆盖产品库 |

沿用且不可改：合法边只在 `TRANSITIONS`；没有 skip-qa；生成中不能改目录；属地库按属地过滤；交付物是 Word；主 agent 不搜网写正文。

## 3. 对象与分层

知识库不是单一袋子，按**库角色**分：

| `library` | 内容 | 写章用法 |
|---|---|---|
| 产品库 | 本公司方案、设备与平台口径、可核验参数 | 全章可用；质检 `canonical_params` 仍以此为准 |
| 风格库 | 体例、章法、用语，不含具体市情和文件名 | 全章可用；禁止当地方文件引用 |
| 地方库 | 已整理的属地规划/政策条目 | 仅当 `place` 与当前画像属地匹配 |
| 历史库 | 历史项目全文（建议书/可研/立项等） | 按第 5 节双通道召回 |
| 检索 | 本次任务 DeepSeek 网页检索命中 | 仅地区/政策槽；须属地匹配；确认后才写正文 |

现行 `backend/knowledge/**/*.json` 是产品库 / 风格库 / 地方库的种子，不删除。历史库上线后，JSON 地方库与 RAGFlow 地方/历史命中在 8002 合并去重，规则相同。

## 4. 元数据

每份入库文档（及切出的 chunk）必须带下列字段。文件夹名可作初值，人工或规则可改，**缺 `doc_type` / `place` / `stage` 的文档允许入库，禁止进入写章召回**。

| 字段 | 取值 | 来源示例 |
|---|---|---|
| `place` | 市/县全称，如「登封市」「青岛市」 | 文件夹「登封市低空经济申债项目」 |
| `direction` | `low_altitude_economy` 低空经济建设；`low_altitude_public_security` 低空公安警务 | 文件夹含「警务/公安/巡检」→ 后者，否则前者（不确定标 `unknown`，写章默认不召回） |
| `stage` | 见下表 | 人工分夹或文件名 |
| `doc_type` | `initiation` 立项报告；`solution` 项目建议书；`feasibility` 可研报告；空 | 由 `stage` 映射，见下表 |
| `chunk_role` | `locale` 地区/政策/编制依据；`scheme` 建设方案/模块；`investment` 投资/经济；`other` | 标题/小标题关键词，8002 可再判一次 |
| `project` | 历史项目文件夹名 | 目录名 |
| `title` | 文件全称，禁止「相关规划」 | 文件名或文内封面题名 |

### 4.1 阶段枚举与写章资格

| `stage` | 含义 | `doc_type` | 写章召回 |
|---|---|---|---|
| `pre_opportunity` | 商机前汇报交流材料 | 空 | 否 |
| `research` | 调研阶段 | 空 | 否 |
| `initiation` | 立项阶段 | `initiation` | 仅当前任务文类为立项 |
| `proposal` | 建议书（若材料在立项/调研夹中但文本是建议书，应改标此档） | `solution` | 仅当前任务文类为建议书 |
| `feasibility` | 可研阶段 | `feasibility` | 仅当前任务文类为可研 |
| `preliminary_design` | 初设阶段 | 空 | 否 |
| `tender` | 招投标阶段 | 空 | 否 |
| `other` | 其他 | 空 | 否 |

「写项目建议书就参考历史项目建议书」以 **`doc_type` 相等** 为准，不以文件夹层数为准。夹在「立项阶段」下的建议书 Word，入库时 `doc_type=solution`。

方向与画像：`profile.industry` 含「公安 / 警务 / 巡检」则匹配 `low_altitude_public_security`，否则匹配 `low_altitude_economy`。方向不一致的历史文档不进写手。

## 5. 双通道召回

8002 在写章前（或按章）向 RAGFlow `POST /api/v1/retrieval` 取候选，然后**本地再滤一遍**。RAGFlow 的 `metadata_condition` 只当加速，不能当唯一闸门。

地区/政策写作槽（与现网一致）：`overview`、`background`、`initiation_basis`，以及标题含「概述 / 背景 / 立项依据」的章。

### 通道 A：地区 / 政策

允许进入这些章的 `Citation` 仅来自：

1. `library=地方库` 且 `place` 与画像属地匹配（现有 `place_key` 规则）；
2. `library=历史库` 且 `doc_type` 等于当前任务、`place` 匹配、`chunk_role=locale`、`direction` 匹配；
3. `library=检索` 且属地匹配，且已通过方向确认（第 8 节）。

禁止：外地历史的地区/政策 chunk；风格库条目冒充地方文件；未确认的网页检索。

### 通道 B：方案 / 投资 / 其他非地区章

允许：

1. 产品库、风格库（风格库不得点名为地方文件）；
2. `library=历史库` 且 `doc_type` 相等、`direction` 匹配、`chunk_role` ∈ {`scheme`,`investment`,`other`}。

即使历史项目在登封，只要不是 `locale` chunk，可以给青岛稿的建设方案、投资写法作参考。正文仍须用当前画像的地名、投资、模块；历史数字不能覆盖画像和产品库参数。

### 提示词与引用

命中写入 `job.citations`，`library` 为上表之一。写章提示词只列出清单内 `title`。禁止写「XX市相关规划」「有关部门文件」。历史库引用须写文件全称，并不得把外地文件写成当前属地文件。

## 6. 使用流程（操作者不可见存储）

操作者仍只在 http://127.0.0.1:3080/ 说话。知识库不出现侧栏。

1. 运维按项目文件夹入库 RAGFlow，补齐第 4 节元数据。
2. 操作者完成画像与目录确认。
3. 8002 做属地实时检索，复述政策方向，人确认后再写正文（第 8 节；实现前仍为「检索完立刻写」，本规范要求改为确认后写）。
4. `write-chapters`：通道 A + 通道 B 召回 → 注入提示词 → 写全部正文。
5. 质检按第 7 节。失败只能改写或换产品库素材，不能 skip-qa。

3080 agent 不得对 RAGFlow 或公开网页自行检索后写章节正文。

## 7. 质检

保留现有：

- `LOC-01`：概述/结论点名属地。
- `LOC-02`：地区/政策章禁止空泛「相关规划/有关政策」；有「检索」或「地方库」命中须点名标题。
- 产品参数与产品库一致。

新增（实现本规范时一并落地）：

| 代码 | 规则 |
|---|---|
| `KB-01` | 地区/政策章点名的历史文件，必须能在通道 A 的 `citations` 里找到；点名外地 `place` 的历史题名则失败。 |
| `KB-02` | 建议书正文不得把可研专有深度（IRR/NPV 等）当成已引用历史可研而写进建议书，除非当前 `doc_type` 为可研。 |

## 8. 与属地检索确认的关系

实时检索不在 RAGFlow 内完成。8002 用 DeepSeek Responses API `web_search`，属地过滤，最多 5 条 `library=检索`。

已共识、尚未实现的写前确认（不改 `TRANSITIONS`）：

1. 目录确认后、开写前：`draft-locale-brief` 出一段方向综述（含 0 命中时的「只写国家/行业政策、不编地方文件名」）。
2. 人可改综述、重搜或补文件名，再出新综述。
3. `confirm-locale-brief` 之后才允许 `write-chapters`。
4. 质检改写沿用已确认口径，除非人要求重搜。

知识库通道 A 与已确认检索清单在提示词里合并。人确认的是**本属地政策方向**，不是外地历史项目。

## 9. RAGFlow 接入约定

- 独立进程。8002 经 API Key 调检索/（可选）上传。
- 建议按库角色分 dataset：产品 / 风格 / 地方 / 历史；历史库也可按 `doc_type` 再分，便于预过滤。
- 属地过滤以 8002 后过滤为准。
- 不使用 RAGFlow 对话助手作为章节写手。
- 解析失败的文件：标记 `stage` 可保留，不进写章召回。
- 密钥只放环境变量，不进仓库、不进 skill 正文。

现行无 RAGFlow 时：`retrieve()` 继续读 `backend/knowledge/` JSON；历史库通道返回空。不得假装已召回 10G 材料。

## 10. 测试

- 青岛建议书：登封可研的地区/政策 chunk 不出现在概述/背景提示词；登封建议书的建设方案 chunk 可以出现在建设方案提示词，且不得把「登封市」写成青岛地方文件。
- 写建议书：可研 `doc_type` 文档不进任何章的历史库引用。
- 初设/招标/调研/商机前：入库后写章召回为空。
- 方向：公安巡检任务不召回纯「低空经济」历史（`direction` 不一致）。
- 无 RAGFlow、无 Key：JSON 三库仍可用；不抛未捕获异常。
- `LOC-02` 不因历史库外地文件而放行空泛「相关规划」。
- `TRANSITIONS` 表与现文件一致。

## 11. 非目标

- 不改 `machine.py` 的 `TRANSITIONS`。
- 不在 3080 做知识库 UI。
- 不把社区 dsh 知识库插件（PowerContext、dsh-knowledge-sqlite、DeepTutor）当作编制依据来源。
- 本期不把初设、招标做成新 `DocType`。
- 不让历史文档覆盖产品库参数和画像投资/工期。
- 不在本规范实现期内做自动全量 10G 爬目录入库脚本（另开运维手册）。
